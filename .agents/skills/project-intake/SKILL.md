# Project Intake Skill (最初の受け口)

依頼文がまだどこにも無い状態で、**1案件につき1回だけ**「何を作るか」を利用者から受け取る手順です。
受け取ったら、追加で聞かずに [`project-spec` スキル](../project-spec/SKILL.md) 手順1へ渡します。

> **なぜ独立した手順か**: [`session-checkin`](../session-checkin/SKILL.md) は「前セッションの続きを続ける」手順であり、続きが無い最初の1回を持ちません。
> `project-spec` は「依頼文から読み取れる内容で埋める」手順であり、依頼文そのものを受け取る場面を持ちません。
> その隙間の1回だけがここです。**ここに入る回数が案件数を超えたら、この手順は失敗しています**（AGENTS.md 避けるべき未来3位）。

## 起動条件 (Triggers)

次の3つが**すべて**成り立つときだけ起動します。1つでも欠けたら起動せず `project-spec` 手順1から始めます。

1. `spec.md` 第1節・第2節の記入欄が空である。
2. git 履歴・`docs/handoff.md` に依頼の内容が無い。
3. 現在の会話にも依頼文が無い。

## 手順 (Workflow)

1. **現在地を1〜2行で述べる。** 長い状態報告を先に書かない。利用者が最初に読むのは尋ねられている内容であるべきです。
2. **下の文言で呼びかける。** 口調はコンシェルジュです。手続きの案内文にしません。
3. **返答が来たら、埋まらない箇所だけを、まとめて1回で尋ねる。** 細切れに何度も往復しません。文言で「足りないところは私からお尋ねします」と約束している以上、黙って想像で埋めるのは約束と違います。
4. **それでも埋まらない箇所は、最も確からしい案で埋めて `project-spec` 手順1へ渡す。** 相手が答えられない部分を粘って聞き出しません。判定はGate 1の二択が行います。

## 文言 (Wording)

**口調はコンシェルジュです。** 手続きの案内係ではありません。要望を「教えてもらう」立場ではなく、「承って形にする」立場で話します。
下の文をそのまま使い、案件に合わせて例だけ差し替えます。

```text
初回のセットアップを承ります。

まずは、作りたいものを聞かせてください。かしこまらずに、思いついたままで大丈夫です。
「誰が使うのか」「その人のどんな手間が減るとうれしいか」——このあたりが一言でも入っていれば、
あとはこちらで形にできます。

たとえば、こんな粒度で十分です。

- 「店長が月末にやっている売上の集計を、画面でぱっと終わらせたい」
- 「予約の受付を、電話じゃなくてネットでできるようにしたい」

うまくまとまっていなくて大丈夫です。足りないところは私からお尋ねしますので、
お好きなようにお答えください。画面の見た目・使う技術・作る順番は、こちらで考えます。

（この最初のやりとりは1回きりです。次からは、いきなり本題に入れます。）
```

### 書くときの5点

1. **1行目を「承ります」から始める。** 「初回のセットアップ」と名乗った時点で、これが毎回のものではないと伝わります。頻度の宣言を後ろに置くと、読み終える前に「毎回これをやるのか」と判断されます（`docs/failures.md` F-20260826-01）。
2. **書き言葉を話し言葉に置き換える。** 日本語のUXライティングで最も欠けやすいのは人間味であり、「敬語＋書き言葉」をやめて話し言葉にするだけで大きく改善します。「〜する場合は」「〜のため」「〜します」を並べた条件文は、正確でも冷たく読まれます。
3. **例を2つ添える。** 白紙の入力欄だけを渡すのは、何を書けばよいかの学習コストを相手に押しつける形（blank page problem）です。例は**選択肢ではなく粒度の見本**として置きます。技術・画面・手段の例を出しません（AGENTS.md D-2）。
4. **不安を先読みして打ち消す。** ここでの不安は「うまく書けないと進まないのではないか」です。「うまくまとまっていなくて大丈夫」「足りないところは私から尋ねる」を、相手が書き始める前に置きます。
5. **主語を相手に置く。** 「ご記入ください」ではなく「聞かせてください」。手順の説明ではなく、相手への呼びかけとして書きます。

### この場で書かないこと

- Gate 1の二択や、この先の工程の全体像を先に説明しない。**相手が今この瞬間に必要なのは、何を答えればよいかだけ**です。二択は `project-spec` 手順2で自然に出てきます。
- 現在地の報告は1〜2行まで。呼びかけより前に長文を置かない。

## 禁止事項 (Do Not)

- **細切れに往復しない。** 聞き返しは、埋まらない箇所についてまとめて1回まで。1問ずつ投げて相手に何度も戻らせることは、確認回数を案件数に比例させる形そのものです（AGENTS.md 避けるべき未来3位）。
- **案を複数並べて選ばせない。** 「A案とB案どちらがよいですか」は追加のヒアリングであり、評価の負担を相手に移す形です。
- **尋ねる前に長い状態報告を書かない。** 現在地は1〜2行で足ります。
- **選択肢を並べて選ばせない。技術用語で範囲を指定させない**（AGENTS.md D-2、`docs/handoff.md` 禁止事項2〜3）。
- **起動条件を1つでも欠く場面で起動しない。** 会話に依頼文がある時点で、この手順は不要です。
- **Gate 1をここで回さない。** 回すのは `project-spec` 手順2です。
