## 0. 次のセッションが最初に読むべきこと (READ FIRST)

**この案件の依頼者は非エンジニアです。コードを1行も読めません。** 次の担当は Claude とは限りません（Codex / Antigravity も同じリポジトリを触ります）。

### 禁止事項
0. **【最優先】途中経過を実況しない。** 説明は「問題がある」かつ「承認が無いと進めない」の両方を満たすときだけ。必要なのは結果だけである（AGENTS.md D-2）。
0a. **【最優先】利用者が何も言っていないターンでは何も表示しない。** 通知や自動処理だけのターンは黙って終える。「待っています」も出さない（AGENTS.md D-2）。
0b. **【最優先】同じ内容を二度出さない。** 選択肢や手順を再掲しない。待っているなら1行で伝える（AGENTS.md D-2）。
0b-2. **【最優先】自分の操作の反響を報告しない。** 自分が出したPRのマージ通知などは黙って処理する（AGENTS.md D-2）。
0b-3. **【最優先】報告して終わらない。** 返答の最後に「次に何が起きるか」か「次に何をすればよいか」を必ず1行置く。黙って止まらない（AGENTS.md D-2）。
0c. **【最優先】何かを求めるときは、推奨を含む3つの選択肢＋自由文を必ず添える。** 白紙で問いを投げない（AGENTS.md D-2）。
0d. **【最優先】相手が読んで分かるかを、発言前に必ず自問する。** 長さは問わない。形式へのこだわりを、伝わることより優先しない（AGENTS.md D-2）。
1. **エンジニア向け語彙で話さない。** 技術用語は使うが、必要なら定義を添える（AGENTS.md D-2）。
2. **変更範囲をユーザーに技術用語で指定させない。**
3. **技術的な選択肢を並べて選ばせない**（評価にコード知識が要るため）。
4. **手が止まっていないのに確認を投げない。** 確認は `spec.md` を決めるときの二択1回に限る。
5. **規模・頻度・回数を問われたら、まず桁を出す。** 前提を置いてでも数字を先に。
6. **PRを出したら次の作業に移る。** 定期的に様子を見に行かない。

直したこと:

- 手順3を、展開の前に同じ名前のものを調べ、1つでもあれば `要対応` を出して
  **何も書かずに終わる**ブロックへ差し替えた（`index.html` の `buildMarkdown`）。
- 調べる名前の一覧（`KIT_TOP`）は `scripts/build-kit.sh` が現物の一式から拾って
  `index.html` へ埋める。ハッシュ値と同じやり方で、手で書かない。
- B群の①に、その一覧と判定文が指示書に入っていることの確認を足した。
  これまでは「上書き」という語があるかしか見ておらず、語だけの状態が緑になっていた。
- `docs/failures.md` に F-20260827-10 として記録した。

**証拠（赤／緑／戻して赤）**:

- 赤: 素の `tar -xzf` が、既存2ファイルを exit 0 のまま置き換えた。
- 緑: 新しいブロックは `要対応` を出し、フォルダの中身が1バイトも変わらなかった
  （`find | shasum` の前後比較が完全一致）。空のフォルダでは `問題なし` を出して展開し、
  `verify-install.sh` まで通った。
- 戻して赤: 手順3を素の1行に戻すと B群①が落ち、実機でも同じ上書きが再現した。
